### Default yang saya pilih sendiri (butuh persetujuan, bagian 9)
- **A1** `querydata`: jawab seperti lama (`options`→`OK`, `count`→perbarui jumlah, `tabledata`→`<tablename>=<count>`), tanpa menarik log lama dari mesin.
- **A2** Duplikat lintas mesin (pegawai sama, waktu sama, dua mesin): log mentah keduanya disimpan, **punch hanya satu**.
- **A3** Ambang suspect: `punched_at > received_at + 500 detik` (nilai kode lama), dapat diatur lewat env ADMS.
- **A4** "Terlalu lama": waktu mesin sebelum `2020-01-01` (batas kode lama untuk ATTLOG), dapat diatur lewat env.
- **A5** Polling default 60 detik (log produksi lama menunjukkan `getrequest` tiap ±62 detik).
- **A6** Template foto wajah (`BIOPHOTO`) ikut disimpan terenkripsi (mengikuti D1 yang menyebut foto wajah).

UI kelola mesin: daftar mesin (status online/offline dari `last_seen_at`), tambah/ubah mesin, antrean perintah per mesin (kirim REBOOT/INFO/CHECK/SET TIME/ADD USER/ADD FP), tinjau log mentah bermasalah (`unknown_pin`, `period_closed`, `employee_inactive`) dengan aksi "proses ulang". ## 3. Tabel

Konvensi v2: snake_case tanpa prefix, `bigint` id, FK + index eksplisit, enum sebagai `varchar` dengan backed enum PHP, `created_at/updated_at` bertipe seperti tabel lain. DDL di bawah memakai sintaks PostgreSQL agar jelas; sesi v2 menuliskannya sebagai migration Laravel.

### 3.1 `devices` (pengganti `device_list` + `serial_list` + `device_temp`)

```sql
CREATE TABLE devices (
    id                   bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    serial_number        varchar(64)  NOT NULL,             -- parameter SN
    name                 varchar(255) NOT NULL,
    region_id            bigint       NULL REFERENCES regions(id) ON DELETE SET NULL,
    location             varchar(255) NULL,
    timezone             varchar(64)  NOT NULL DEFAULT 'Asia/Jakarta',   -- IANA, D11
    is_active            boolean      NOT NULL DEFAULT true,
    device_type          varchar(16)  NOT NULL DEFAULT 'unknown',        -- att | acc | unknown
    model                varchar(64)  NULL,                 -- ~DeviceName
    platform             varchar(64)  NULL,                 -- ~Platform
    firmware_version     varchar(64)  NULL,
    push_version         varchar(16)  NULL,
    ip_address           varchar(45)  NULL,
    registry_code        varchar(32)  NULL,
    poll_delay_seconds   smallint     NOT NULL DEFAULT 60,  -- Delay / RequestDelay (A5)
    error_delay_seconds  smallint     NOT NULL DEFAULT 60,  -- ErrorDelay
    attlog_stamp         varchar(32)  NULL,                 -- Stamp / ATTLOGStamp, apa adanya dari mesin
    operlog_stamp        varchar(32)  NULL,                 -- OpStamp / OPERLOGStamp
    photo_stamp          varchar(32)  NULL,                 -- PhotoStamp / ATTPHOTOStamp
    biodata_stamp        varchar(32)  NULL,                 -- BIODATAStamp
    user_count           integer      NULL,
    fingerprint_count    integer      NULL,
    face_count           integer      NULL,
    log_count            integer      NULL,
    reported_options     jsonb        NULL,                 -- balasan INFO/options mentah, tanpa data pribadi
    first_seen_at        timestamptz  NULL,
    initialized_at       timestamptz  NULL,                 -- pengganti is_new: terisi setelah INFO pertama sukses
    last_seen_at         timestamptz  NULL,                 -- pengganti status/last_activity; semua request mesin
    created_at           timestamp(0) NULL,
    updated_at           timestamp(0) NULL,
    CONSTRAINT devices_serial_number_unique UNIQUE (serial_number)
);
CREATE INDEX devices_region_id_index ON devices (region_id);
CREATE INDEX devices_is_active_last_seen_at_index ON devices (is_active, last_seen_at);  -- laporan mesin offline
```

Catatan:
- **Daftar putih = baris `devices` aktif.** Mesin tak dikenal atau `is_active=false` ditolak di **semua** endpoint (bukan hanya handshake). Menggantikan hash `snini…adalahkatakunci` dan tabel `serial_list`.
- Stamp disimpan **persis seperti dikirim mesin** dan dikembalikan di handshake (`None` bila kosong). Tidak ada penghitungan `now - 935082000` (legacy-analysis 2.2).
- `status = 2` (sibuk) dihapus; tidak lagi dipakai menolak log. Status online dihitung `now() - last_seen_at < 3 × poll_delay_seconds`.
- `is_new` diganti `initialized_at`: bila `NULL`, handshake mengantrekan `INFO` lalu `CHECK` (perilaku lama `iconnect`/`icommand`).
- Kolom kapabilitas biometrik (`fp_fun`, `face_fun`, `*_maximum`, …) tidak dibawa; cukup `reported_options` (jsonb) bila UI memerlukannya.

### 3.2 `device_commands` (pengganti `command_list` + `commands_user`)

Satu tabel, id unik → menyelesaikan tabrakan ID (legacy-analysis 4.2). Nilai `id` dipakai sebagai `C:<id>:…` dan kembali di `devicecmd`.

```sql
CREATE TABLE device_commands (
    id                     bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    device_id              bigint      NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    command_type           varchar(24) NOT NULL,   -- info | check | reboot | set_time | add_user | add_fingerprint
    priority               smallint    NOT NULL,   -- 1 sistem, 2 pengaturan, 3 user, 4 jari/wajah (kelas flag lama)
    status                 varchar(16) NOT NULL DEFAULT 'pending',  -- pending | sent | succeeded | failed | cancelled
    employee_id            bigint      NULL REFERENCES employees(id) ON DELETE CASCADE,            -- add_user, add_fingerprint
    biometric_template_id  bigint      NULL REFERENCES biometric_templates(id) ON DELETE CASCADE,  -- add_fingerprint
    attempts               smallint    NOT NULL DEFAULT 0,
    requested_by           bigint      NULL REFERENCES users(id) ON DELETE SET NULL,
    available_at           timestamptz NOT NULL DEFAULT now(),
    sent_at                timestamptz NULL,
    completed_at           timestamptz NULL,
    return_code            integer     NULL,        -- Return= dari mesin
    result_message         varchar(255) NULL,
    created_at             timestamp(0) NULL,
    updated_at             timestamp(0) NULL
);
CREATE INDEX device_commands_poll_index ON device_commands (device_id, status, priority, id);
CREATE INDEX device_commands_employee_id_index ON device_commands (employee_id);
CREATE INDEX device_commands_biometric_template_id_index ON device_commands (biometric_template_id);
CREATE INDEX device_commands_requested_by_index ON device_commands (requested_by);
-- satu perintah pemeliharaan sejenis yang aktif per mesin (menggantikan firstOrCreate(serial_no, command))
CREATE UNIQUE INDEX device_commands_active_maintenance_unique
    ON device_commands (device_id, command_type)
    WHERE status IN ('pending', 'sent') AND command_type IN ('info', 'check', 'set_time');
```

Alur:
- **Poll (`getrequest`)**: pilih satu kelas prioritas terkecil yang punya `pending` dan `available_at <= now()`, batas per poll seperti lama (kelas 1: 1, kelas 2: 10, kelas 3: 50, kelas 4: 5), `SELECT … FOR UPDATE SKIP LOCKED`, tandai `sent` + `sent_at` + `attempts+1`. Mesin tanpa perintah → `OK`.
- **Hasil (`devicecmd`)**: `Return=0` → `succeeded`; selain itu `failed` + `return_code` (berbeda dari lama yang menandai kegagalan `DATA`/`REBOOT` sebagai sukses). `CMD=INFO` juga memperbarui `devices` dan mengisi `initialized_at`.
- **Tak ada jawaban**: `sent` lebih tua dari `COMMAND_ACK_TIMEOUT_SECONDS` (default 120, env ADMS) kembali `pending`; setelah 3 percobaan `failed` (`result_message='tidak ada jawaban'`). Menghilangkan kirim-ulang tanpa batas pada `commands_user`.
- **Isi perintah** dirakit saat kirim dari data terkini, bukan disalin ke tabel: `add_user` dari `employees` (PIN = `employee_number`, nama dibersihkan dari tab/newline), `add_fingerprint` dari `biometric_templates` (didekripsi di ADMS). Bentuk baris `DATA …` pada firmware nyata harus dikonfirmasi di Task 4 (legacy-analysis bagian 10).
- `set_time` menghasilkan `SET OPTIONS MachineTZ=±HHMM` dan `SET OPTIONS DateTime=<detik ZK>` dari `devices.timezone`; ADMS juga menjadwalkan `set_time` otomatis bila selisih jam mesin besar atau berkala (tidak sekali seumur hidup seperti lama). Perintah mentah `SET ABCPIN` lama tidak dibawa kecuali terbukti perlu di Task 4.
- Perintah dibuat oleh: operator lewat UI v2 (`requested_by` terisi) atau ADMS sendiri (`NULL`, mis. `info`/`check` saat mesin baru terhubung).

### 3.3 `device_logs` (pengganti `transaction_logs` + `trans_suspects`; log mentah)

```sql
CREATE TABLE device_logs (
    id           bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    device_id    bigint       NOT NULL REFERENCES devices(id) ON DELETE RESTRICT,
    pin          varchar(32)  NOT NULL,                 -- apa adanya dari mesin, tanpa padding (D9)
    device_time  timestamp(0) NOT NULL,                 -- waktu lokal mesin persis seperti dikirim (tanpa zona)
    punched_at   timestamptz  NOT NULL,                 -- device_time di devices.timezone → UTC
    io_status    smallint     NULL,                     -- function_key lama (masuk/keluar di mesin)
    verify_mode  smallint     NULL,                     -- cara verifikasi (jari/wajah/kartu/password)
    received_at  timestamptz  NOT NULL DEFAULT now(),
    source_ip    varchar(45)  NULL,
    employee_id  bigint       NULL REFERENCES employees(id) ON DELETE SET NULL,
    punch_id     bigint       NULL REFERENCES attendance_punches(id) ON DELETE SET NULL,
    outcome      varchar(24)  NOT NULL,                 -- lihat enum di bawah
    is_suspect   boolean      NOT NULL DEFAULT false,   -- D4: punched_at > received_at + ambang
    created_at   timestamp(0) NULL,
    updated_at   timestamp(0) NULL,
    CONSTRAINT device_logs_device_pin_time_unique UNIQUE (device_id, pin, device_time)   -- kunci idempotensi
);
CREATE INDEX device_logs_employee_id_index ON device_logs (employee_id);
CREATE UNIQUE INDEX device_logs_punch_id_unique ON device_logs (punch_id) WHERE punch_id IS NOT NULL;
CREATE INDEX device_logs_punched_at_index ON device_logs (punched_at);
CREATE INDEX device_logs_review_index ON device_logs (outcome, device_id) WHERE outcome <> 'punched';
```

`outcome` (`DeviceLogOutcome`):

| Nilai | Arti | Punch dibuat? | Bisa diproses ulang? |
|---|---|---|---|
| `punched` | Dipetakan ke pegawai aktif dan punch dibuat | ya | n/a |
| `unknown_pin` | PIN tak cocok dengan `employee_number` (D9) | tidak | ya, setelah pegawai/PIN dibereskan |
| `employee_inactive` | Pegawai cocok tapi `is_active=false` | tidak | ya |
| `period_closed` | Bulan (zona `attendance.timezone`) periode berstatus bukan `open` (D10) | tidak | ya, bila periode dibuka kembali |
| `out_of_range` | Waktu sebelum batas A4 | tidak | tidak |
| `duplicate` | Sudah ada punch `approved` pegawai yang sama pada `punched_at` yang sama (A2) | tidak | tidak |

Catatan desain:
- **Kunci unik memakai `device_time` (waktu lokal mentah)**, bukan `punched_at`. Bila zona mesin diubah di UI, kiriman ulang batch lama tidak membuat baris ganda.
- Berbeda dari lama, kunci memuat mesin (`device_id`), sesuai aturan CLAUDE.md.
- `punch_id` unik (parsial) → satu log menghasilkan paling banyak satu punch; bersama transaksi tunggal (bagian 4) menjamin kiriman ulang tidak menambah punch.
- `ON DELETE RESTRICT` pada `device_id`: mesin dinonaktifkan, bukan dihapus, selama masih punya log.
- Ukuran: 100 mesin × ratusan log/hari masih ringan untuk satu tabel tanpa partisi; kebijakan retensi diputuskan operasional (bagian 9, Q5).

### 3.4 `biometric_templates` (pengganti `employee_fp`; data pribadi sensitif)

```sql
CREATE TABLE biometric_templates (
    id                bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    employee_id       bigint       NOT NULL REFERENCES employees(id) ON DELETE CASCADE,
    kind              varchar(16)  NOT NULL,            -- fingerprint | face | face_photo
    finger_index      smallint     NOT NULL DEFAULT 0,  -- FID; 0 untuk wajah/foto
    algorithm_version varchar(16)  NOT NULL DEFAULT '', -- FPVersion / FaceVersion; kompatibilitas antar model
    is_valid          boolean      NOT NULL DEFAULT true,
    original_size     integer      NOT NULL,            -- Size dari mesin
    ciphertext        bytea        NOT NULL,            -- AES-256-GCM
    nonce             bytea        NOT NULL,            -- 12 byte, unik per baris
    key_id            varchar(16)  NOT NULL,            -- untuk rotasi kunci
    source_device_id  bigint       NULL REFERENCES devices(id) ON DELETE SET NULL,
    created_at        timestamp(0) NULL,
    updated_at        timestamp(0) NULL,
    CONSTRAINT biometric_templates_identity_unique UNIQUE (employee_id, kind, finger_index, algorithm_version)
);
CREATE INDEX biometric_templates_source_device_id_index ON biometric_templates (source_device_id);
```

Aturan (D1):
- Hanya pegawai dikenal yang dapat memiliki template (`employee_id NOT NULL`); template dari PIN tak dikenal **diabaikan** (tidak disimpan), dihitung di log aplikasi tanpa isi.
- **Enkripsi di ADMS saja** (AES-256-GCM, kunci `BIOMETRIC_KEY` + `BIOMETRIC_KEY_ID` dari env/secret, AAD = `employee_id|kind|finger_index|algorithm_version` agar ciphertext tidak bisa dipindah antar baris). **v2 tidak pernah mendekripsi**; UI v2 hanya menampilkan metadata (jenis, jumlah, mesin sumber, tanggal) dan memicu perintah `add_fingerprint`.
- Template/ciphertext **tidak pernah ditulis ke log**, tidak muncul di pesan error, dan tidak ada di `reported_options`.
- Unik per `(pegawai, jenis, jari, versi algoritma)` sehingga template versi berbeda (model mesin berbeda) tidak saling menimpa.
- Pegawai dihapus → template ikut terhapus (`CASCADE`). Penghapusan saat pegawai berhenti/pensiun dan retensi: bagian 9, Q6.

## 4. Alur penerimaan ATTLOG (Task 5) dan pemetaan ke `attendance_punches`

Per baris `PIN\tYYYY-MM-DD HH:MM:SS\tio\tverify\t…`, dalam **satu transaksi per batch** (rollback seluruh batch bila ada kegagalan DB sehingga mesin mengirim ulang):

1. Mesin harus terdaftar dan `is_active`; jika tidak → tolak (D2), tidak ada data disimpan.
2. `device_time` = waktu mentah; `punched_at` = `device_time` di `devices.timezone` → UTC.
3. `INSERT INTO device_logs … ON CONFLICT (device_id, pin, device_time) DO NOTHING RETURNING id`. Konflik = kiriman ulang → **berhenti untuk baris ini** (tidak ada punch baru). Nilai balik jumlah baris tetap dihitung agar mesin menganggap batch diterima.
4. `is_suspect = punched_at > received_at + ambang` (A3).
5. Tentukan `outcome`: waktu < batas A4 → `out_of_range`; cari `employees.employee_number = pin` → tak ada: `unknown_pin`; tidak aktif: `employee_inactive`; bulan `punched_at` (zona `attendance.timezone`, sama dengan `PeriodGuard` v2) berada di periode tidak `open`: `period_closed`; sudah ada punch `approved` dengan `(employee_id, punched_at)` sama: `duplicate`; selain itu `punched`.
6. Bila `punched`: `INSERT INTO attendance_punches` lalu isi `device_logs.punch_id`, `employee_id`.

| Kolom `attendance_punches` | Nilai dari mesin |
|---|---|
| `employee_id` | `employees.id` hasil cocok `employee_number = pin` |
| `punched_at` | `device_logs.punched_at` (UTC) |
| `source` | `'device'` (kasus baru `PunchSource::Device`) |
| `status` | `'approved'` (D3), termasuk log `is_suspect` (D4b) |
| `created_by`, `reviewed_by`, `reviewed_at`, `photo_path`, `latitude`, `longitude`, `accuracy_meters` | `NULL` |
| `note` | `NULL` (asal mesin ditelusuri lewat `device_logs.punch_id` → `device_id`) |

`attendance_punches` tidak punya kolom arah masuk/keluar; `io_status` hanya tersimpan di log mentah (kalkulator v2 menentukan status dari roster + urutan punch).

Pemrosesan ulang (`unknown_pin`, `employee_inactive`, `period_closed`) dilakukan **dari UI v2** (aksi "proses ulang" per log atau per mesin). Aturan yang sama dengan langkah 5-6 sehingga perlu ditulis di Laravel dan Rust; keduanya diuji dengan kasus yang sama (kontrak lintas repo seperti aturan periode terkunci di `CLAUDE.md` v2).

## 6. Akses database dan keamanan

- ADMS memakai **role Postgres sendiri** (bukan pemilik skema): `SELECT` pada `employees`, `periods`, `regions`; `SELECT/UPDATE` pada `devices`; `SELECT/INSERT/UPDATE` pada `device_commands`, `device_logs`, `biometric_templates`; `INSERT` pada `attendance_punches` (+ `SELECT` untuk cek duplikat). Tidak ada hak DDL, tidak ada akses ke `users`.
- Rahasia hanya dari env: `DATABASE_URL`, `BIOMETRIC_KEY`, `BIOMETRIC_KEY_ID`.
- Tidak ada hash/rahasia terbenam di kode (legacy-analysis 8, #16). Endpoint selain `ping` menolak mesin tak terdaftar.
- Log aplikasi memuat serial, jenis event, jumlah baris; **tidak** memuat isi body biometrik, dan PIN hanya bila perlu pemecahan masalah.

## 7. Contoh balasan yang tidak berubah oleh keputusan ini

Kompatibilitas protokol tetap mengikuti legacy-analysis bagian 3 (balasan `OK`, `OK:<n>\n`, `C:<id>:<cmd>\n`, opsi handshake). Karena D6/D7 mengabaikan OPERLOG/rtlog/ATTPHOTO, ADMS tetap membalas `OK`/`OK\n` agar mesin tidak mengirim ulang; `Realtime=1` dan `TransFlag` handshake dipertahankan seperti lama sampai diuji dengan mesin/simulator (Task 4/6).
